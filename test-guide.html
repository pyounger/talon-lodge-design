Test guide — walk each process

Concrete steps with example values for every tool built so far. Open a tool, follow its rows in order, and check each ✓ expected result. Rows marked ⛔ are meant to fail — that's the guard working.

Before you start — how the demo data works.
  • Each tool keeps its own working copy in your browser (localStorage). It's safe to click around — nothing touches the live site.
  • Every tool seeds real sample data on first open, so each test below stands on its own.
  • To start any tool fresh, use its Reset button (or reload after clearing) — noted where it matters.
  • Open each tool link in a new tab so you can keep this guide beside it.

PROCESS 1

Team — add, assign, and archive without losing history

Proves: crew move between boats freely, and removing someone keeps their past (archive, not delete).

Open Team Management ↗
#Do this (example)You should see
1Open the Boats tab. Note Roamer — captain Travis Stephenson, deckhand CJ Tacada.6–7 boats, each with a captain/deckhand dropdown you can change.
2On Roamer, change the deckhand dropdown to Porter Baskin.Crew reassigns instantly — proves crew aren't locked to one boat.
3Go to Captains tab → find Travis Stephenson → click ⊘ Archive → confirm.Travis disappears from the active list; the count drops by one; Roamer's captain slot is now empty (a former employee can't crew a live boat).
4Click Show former (1) at the top-right of the list.Travis reappears greyed out, badged Former · left [today], with a Restore button.
5Click Restore on Travis.He returns to the active list; count goes back up. (His Roamer slot stays empty until you reassign — intentional.)
6Go to Guides tab → on Holden Pucket, toggle the capability chip Kayak & Lunch on.Chip highlights — Holden is now capable of kayak trips (feeds the scheduling engine, Process 4).
PROCESS 2

Activities — set where each one can be requested

Proves: an activity can be hidden from the reservation flow and offered only on the guest portal.

Open Activities Management ↗
#Do this (example)You should see
1Click Additional Saltwater Sportfishing in the left list.The editor opens with its details, pricing, and availability.
2Scroll to Where guests can request this → click Portal only → click Save activity.The list row gets a green portal only tag.
3Open View as asset JSON at the bottom of the editor.The JSON shows "offer_channel": "portal" — this is what seeds production.
4Set it back to Reservation + Portal → Save.The portal only tag disappears (the default is offered everywhere).
5Click + New → name it Bear Viewing Flight → set Portal only → set a price → Save.New activity appears tagged portal only, ready to offer post-booking.
PROCESS 3

Packages — dates that drive the whole calendar

Proves: a package's arrival date + nights define the bookable trip, and bulk edits apply in one click.

Open Package Management ↗
#Do this (example)You should see
1Click a package (e.g. the May 24, 2027 Sportfishing one).Editor shows arrival date, nights, series, and per-room rates.
2Change Nights from 4 to 5.The title/date-range preview updates live (departure shifts a day later).
3Change Series to Winemaker Series.The auto-title switches to the Winemaker naming.
4In the top bulk databar, set surcharge to 0 → click Set on all.Every package's surcharge becomes $0 at once — no re-import, existing edits kept.
5Click Export.A packages.json downloads — the file that seeds production.

Deposit ($1,000/person) lives in Settings (Process 6), not per-package — so you set it once.

PROCESS 4

Availability & scheduling — the hard part

Proves: bookings sit on real package dates, need a name, fill lead-first, and can't double-book.

Open Availability & Scheduling ↗
⚙️ Fresh start: click Clear all bookings (top-right) before you begin, so counts start empty.
#Do this (example)You should see
1Pick a package in the dropdown: Sportfishing · Mon May 24 · 4n.Columns become real dates: Mon May 24 (arrival) … Fri May 28 (departure); middle days tagged stay.
2Leave the group name blank. Set party 4. Try to + Book ATV Safari on Tue May 25.Blocked — the name field flashes red, nothing books. Every booking needs a name.
3Type group name Younger Group → + Book ATV Safari on Tue May 25.Cell shows Younger Group · 4p · Ted+Holden — the engine assigned the lead guide first.
4Look at Kayak & Lunch and Whale Watching on the same Tue May 25.Both now say Full — Ted was the only guide for them and he's taken. That's the bottleneck.
5Change the name to Smith Group → + Book Massage on Tue May 25.Books fine — massage is a separate resource. Two groups, same day, no conflict.
6Set party to 8. Look at any guided activity on a stay day.Shows Request only — parties over 6 route to admin, they don't auto-book.
7Set party to 2. Look at Additional Saltwater Day on Mon May 24.needs 4+ — saltwater hides under the minimum. Bump to 4 and it opens on travel days only.
8Reload the page.Your bookings are still there — they're saved against the real dates.
9Check the Resource board below the calendar.Each guide / massage-slots / saltwater row shows who holds what, by date and group.
PROCESS 5

Reservation booking — the guest's path

Proves: the 9-step flow, the guest-email rule, the payment schedule, and the cancellation gate.

Open Reservation Booking ↗
#Do this (example)You should see
1Pick a season/date card, e.g. May 24, 2027, party 4. Advance through Rooms and pick one.Each step advances; the running total reflects the package rate × party.
2Your details: enter the lead's name + email, e.g. phil@talonlodge.com.Accepts and moves to the Guests step.
3Guests: add a guest name but leave their email blank → try Continue.Blocked — guest email is required.
4On that guest click ↳ Use group lead email.The lead's email fills in (for kids with no email) — now Continue works.
5Activities: add a couple, then go to Review.Each activity shows its cost + fees payable upon checkout.
6Read the payment schedule at the bottom of Review.Package rate, then $1,000/person due now, balance due 120 days before arrival, and a note that State & City taxes & fees are added to the balance.
7Click Continue to deposit.A Cancellation policy pops up recommending travel insurance — you must click I understand to proceed.
8Deposit: choose Credit card.A separate Card processing fee line item appears; the clean $1,000/person deposit shows without it for other methods.
PROCESS 6

Settings — the global knobs

Proves: deposit, card fee, and cancellation policy are set once and drive the booking flow.

Open Settings ↗
#Do this (example)You should see
1Find Deposit basis → confirm Per person, amount $1,000.Switching to Flat would make it $1,000 per reservation instead of per guest.
2Check the Card processing fee %, e.g. 2.99%.This is the rate the reservation deposit step adds as its separate line item.
3Read the Cancellation policy text + link fields.Editable policy text and the talonlodge.com/cancelation-policy link — this is what the gate in Process 5 shows. Paste your real terms here.
Integration tests — how the tools feed each other

These show the payoff of doing setup first. They rely on the tools sharing one browser storage, so run them from the real app or the same served folder. In the standalone demo files each tool has its own copy, so a change in one may not carry into another — that's expected, not a bug.
